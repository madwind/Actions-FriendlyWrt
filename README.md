# R28S FriendlyWrt

A customized NanoPi R28S build based on FriendlyElec's `Actions-FriendlyWrt` project.

This repository focuses on a smaller R28S firmware, faster repeated builds, and keeping only the components that are actually useful on the device.

## Main changes

### Leaner FriendlyWrt userspace

- Based on OpenWrt / FriendlyWrt `25.12`.
- Removes FriendlyWrt's large set of explicit package selections and returns to a userspace package set close to the OpenWrt `rockchip/armv8` release defaults.
- Keeps the core LuCI, networking, wireless, and system-management packages required for a normal router installation.
- Keeps the Wi-Fi components required by the R28S build.
- Disables unnecessary build outputs and broad package selection options:
  - `CONFIG_ALL_KMODS`
  - `CONFIG_ALL_NONSHARED`
  - `CONFIG_BUILDBOT`
  - SDK
  - Image Builder
  - Toolchain artifacts
- Does not preinstall `kmod-usb-net-rtl8152` or `r8152-firmware`, which are not required by the R28S onboard Ethernet hardware.
- Restores OpenWrt's default empty root password instead of FriendlyWrt's preset password. Set a password after the first login.

### Leaner kernel build

The R28S kernel still uses FriendlyElec's original kernel source and build flow. Only small patches are applied to skip extra components that are not needed for this target.

The build does not compile:

- The external `r8125` driver.
- `cryptodev-linux`.
- The additional `rtw88/8822ce` backport.
- The generic batch of third-party USB Wi-Fi drivers.

FriendlyElec's original R28S kernel configuration and board support are otherwise kept intact.

The following kernel options are additionally enabled:

```text
CONFIG_NET_ACT_CT=m
CONFIG_NET_ACT_CTINFO=m
```

### FriendlyElec local APK repository retained

The local APK repository generated by FriendlyElec is intentionally kept in the final firmware image.

This allows packages produced by the same firmware build to remain installable after flashing. This is especially important for optional `kmod-*` packages because kernel modules must match the exact kernel ABI used by the firmware.

The repository configuration under `/etc/apk/repositories.d/` is therefore left unchanged by this project.

### No upgrade package

Releases only publish the final disk image:

```text
R28S-Zero2-NEO3Plus-Series-FriendlyWrt-25.12.img.gz
```

The additional `images-*.tgz` upgrade package is not generated or published.

## GitHub Actions build improvements

The workflow is split into separate jobs for:

- FriendlyWrt
- U-Boot
- Kernel
- Image assembly

FriendlyWrt, U-Boot, and Kernel are built independently, then their artifacts are collected by the final Image job. This avoids running the complete build pipeline sequentially.

Two GitHub Actions caches are used:

- `friendlywrt/dl` for downloaded OpenWrt source archives.
- `friendlywrt/.ccache` for compiler output.

`CONFIG_CCACHE=y` is enabled in the OpenWrt configuration so repeated builds can reuse compiler output when only a small part of the configuration changes.

## Build with GitHub Actions

Open:

```text
Actions -> Build FriendlyWrt -> Run workflow
```

After a successful build, the final `.img.gz` image is uploaded to the GitHub Release created for that run.

## Local build

A local build helper is provided:

```sh
bash custom/r28s/build-local.sh
```

The script continues to use FriendlyElec's official `build.sh` entry points and only applies the R28S-specific configuration and patches where required.

Build flow:

1. Sync FriendlyElec sources.
2. Apply the reduced FriendlyWrt configuration.
3. Download package sources.
4. Build U-Boot.
5. Build Kernel and FriendlyWrt in parallel.
6. Assemble the final image through FriendlyElec's official `sd-img` path.

## R28S runtime tuning

`r28s-tune` is not baked into the firmware. It is provided as an optional runtime installer.

Run this command on the R28S when needed:

```sh
wget -qO- https://raw.githubusercontent.com/madwind/Actions-FriendlyWrt/master/custom/r28s/install-tune.sh | sh
```

If `ethtool` is missing, the installer installs it directly with the available package manager. It does not run an explicit package-index update first.

The installer creates a tuning script that runs at boot and whenever an interface comes up.

Current tuning includes:

- Disable OpenWrt `packet_steering`.
- Pin IRQ 48 to CPU1.
- Configure the `eth0` and `eth1` RPS CPU masks.
- Disable the RFS flow table.
- Enable SG / TSO / GSO on `eth1`.
- Load `tcp_bbr` when available and switch TCP congestion control to BBR.

The tuning can also be reapplied manually:

```sh
/usr/sbin/r28s-tune
```

## Repository layout

```text
custom/r28s/
├── config.sh                 FriendlyWrt package and build configuration
├── kernel-config.sh          R28S kernel configuration delta
├── host.sh                   CI/local environment setup and source sync
```

## Upstream

This project is based on FriendlyElec's official repository:

https://github.com/friendlyarm/Actions-FriendlyWrt

FriendlyElec's original `build.sh`, kernel build flow, image assembly flow, and local APK repository remain the base of this project. This repository only maintains the R28S-specific differences required for the customized build.
